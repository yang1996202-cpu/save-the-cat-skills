# 救猫咪故事创作 skill 套件

基于布莱克·斯奈德《救猫咪》三部曲的微信读书划线摘录整理。目标不是把书压成一叠检查表，而是让一个没有编剧基础的人，从模糊点子一路走到可读可演的故事正文，同时能查清每条方法来自哪里。

当前结构是 **1 个母编排器 + 6 个单一职责执行 skill**。

## 它们是什么关系

```text
模糊方向
  ↓ stc-idea-check
故事核心卡
  ↓ stc-beatsheet
三个世界 + 十五拍
  ↓ stc-scene-cards
场景卡
  ↓ stc-scene-write
场景正文
  ↓ stc-diagnose
改稿优先单
```

`stc-create` 站在这条链路上方，只判断现在走哪一步、管理交接和回退，不亲自执行任何一步。`stc-first-aid` 是旁路急救：创作者本人想不出来时短暂调用，解卡后回到原步骤。

## 7 个 skill

| 类型 | skill | 一次只干什么 | 输入 → 唯一交付物 |
|---|---|---|---|
| 母编排器 | `stc-create` | 识别阶段、调度、保存产物、管理确认与回退 | 当前材料 → 下一步路由与阶段进度 |
| 点子 | `stc-idea-check` | 把模糊方向发展成故事核心 | 点子 → 故事核心卡 |
| 结构 | `stc-beatsheet` | 铺出整体转变和 BS2 结构 | 故事核心卡 → 三个世界 + 十五拍 |
| 分场 | `stc-scene-cards` | 把节拍拆成可逐场写作的计划 | 节拍表 → 场景卡 |
| 写作 | `stc-scene-write` | 把确认的卡片真正写成场景 | 场景卡 → 场景正文 |
| 查改 | `stc-diagnose` | 按文本证据找问题、排改稿顺序 | 成稿/片段 → 改稿优先单 |
| 急救 | `stc-first-aid` | 让卡住的创作者重新开始动作 | 明确卡点 → 一种方法 + 一个立即动作 |

`stc-idea-check` 的名字为兼容旧调用暂时保留，实际定位已经从“给点子打分”改为“帮点子长成故事核心”。

## 故事创作主线

这套方法共同守住六件事：跟谁走、他哪里过不下去了、他非得到什么不可、谁在拦他、他真正需要学会什么、结尾用什么行动证明他变了。

简化成一句工作语言：

> 一个用旧办法生活的人，为了看得见的目标采取行动；越来越强的阻力让旧办法付出最大代价；他最后以新的选择解决核心冲突，证明自己已经改变。

这不是作者给出的固定公式，而是 `[整理者延伸]`：它把摘录中反复出现的“主角—难题—实体/精神目标—主题—转变”整理成跨 skill 的交接契约。完整说明见 [`references/story-creation-contract.md`](references/story-creation-contract.md)。

## 场景卡不是分镜

`stc-scene-cards` 解决的是“这一场为什么存在”：人物想要什么、遇到什么主要冲突、首尾发生什么变化、结果怎样逼出下一场。

它不输出镜头号、景别、机位、运镜、时长或生成提示词。未来 AI 短剧链路应继续拆开：

```text
故事场景正文 → 独立分镜/镜头设计 skill → 独立 Seedance 提示词 skill → 图片/视频生成
```

这样《救猫咪》负责叙事，分镜 skill 负责镜头表达，Seedance skill 负责模型参数与提示词；三者不会互相污染。

## 原文保护与出处纪律

本项目的主要资料是《救猫咪》三部曲的 **197 条微信读书划线、书评与个人想法，不是三本书全文**。原始文件不复制到公开仓库，也不由本项目修改。

[`references/source-ledger.md`](references/source-ledger.md) 记录：

- 原始文件的行数、字节数和 SHA-256；
- 每组方法对应的原始行号和唯一主责 skill；
- `[摘录]`、`[官方补充]`、`[整理者延伸]` 的区别；
- 从运行时移出的职业、销售和作者经历知识去了哪里。

发布前可运行 `scripts/verify-source.sh /path/to/救猫咪三部曲.md`，只读复核原始文件的哈希、行数和字节数。

从 skill 中删掉一段，不等于把知识扔掉：必须在来源账本中标成“迁移到谁”或“非运行时保留”。这是防止有损压缩的硬规则。

“三个世界”的完整定义是唯一的 `[官方补充]`：本地划线没有该章全文，当前定义补自 Save the Cat 官方 `Transformation Machine` 材料。电影页码、约 40 场和商业包装项迁移到小说、短剧时都只能作为工作尺度，不能当硬指标。

## 设计原则

1. **一个 skill，一个用户时刻，一个交付物。** 子 skill 可独立调用；母 skill 只编排。
2. **生成和检查分开。** 点子、结构、分场和正文阶段先创作；诊断阶段再查错。
3. **不让术语挡住小白。** 先说人话，首次出现再补专业名词。
4. **书中方法与整理者延伸分开。** 找不到来源就不能冒充作者法则。
5. **不为了做 skill 而做 skill。** 只有出现新的稳定用户时刻和独立交付物才新增能力。
