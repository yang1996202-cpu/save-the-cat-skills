# 前向测试记录

日期：2026-07-30

测试方式：把自然用户请求交给独立 agent；agent 只读取被测 skill 及其明确依赖，不读取 `evaluations/` 中的期待答案。以下只记录行为结论，不把长篇生成结果固化成模板。

## FT01 母编排器 → 点子发展

用户请求：只有一句故事点子，最终想做成完整短剧，希望走完整流程。

结果：通过。

- `stc-create` 正确识别当前是点子阶段并委派 `stc-idea-check`。
- 子 skill 交付一张故事核心卡，包含主角、麻烦、实体目标、对抗、内在需要、主题、结尾证明行动和暂定项。
- 没有提前生成十五拍、场景卡、正文或分镜。
- 首次测试在禁止读取子 skill 的人为限制下，母 skill 出现了自行给创意方案的倾向；在允许按编排规则读取子 skill 后通过。因此在母 skill 中补上：宿主无显式调用机制时读取兄弟 `SKILL.md`，依赖缺失时不得凭摘要假装执行。

## FT02 场景卡 → 场景正文

用户请求：把“母女争夺会暴露父亲罪行的旧账本”场景卡写成约两页短剧正文。

结果：通过。

- 输出是完整剧本场景，不是卡片复述或检查报告。
- 账本的藏、找、争夺和撕裂承载主要冲突；母亲的失言完成信息揭示。
- 对白存在试探、回避和权力变化；人物声音可区分。
- 首尾从信任变为背叛，女儿带走关键页并去找父亲，形成下一场因果。
- 未输出镜头号、景别、运镜、时长或生成提示词。

## FT03 诊断与急救边界

请求 A：用户贴文本并说主角到中点后总被别人推着走，要求看哪里有问题。

请求 B：用户知道主角应该主动，但想不出能做什么，明确不要分析全文，只想先动起来。

结果：通过。

- A 路由 `stc-diagnose`：问题对象是已有文本。
- B 路由 `stc-first-aid`：问题对象是创作者当下想不出动作。

## FT04 已作废：超级英雄同题迭代实验

请求：从一句“城市无敌的超级英雄回乡后被当成灾难、想留下保护母亲”的点子，一口气完成故事核心、十五拍、场景卡、约 3 分钟正文和最终诊断。

当时的执行代理没有读取旧答案，每轮也有独立审查；但运行时 skill 在轮次之间根据上一轮错误持续修改，随后又重复使用同一道题。中间版本没有逐轮提交或打标签。

结论：这不是可以用于判断泛化能力的六次盲测，而是一组针对同一道题连续调参的开发实验。更早的问题是，原始点子的关键反差没有先证明成立，流程却继续把它扩展成结构和正文。

- `evaluations/runs/` 保留所有原始产物，仅作为失败过程档案。
- 不把其中的特殊能力、救援设备、专业权限、目标期限或精确时间核验写回通用运行时 skill。
- 不把任何一轮作品当作好故事样例。
- 后续测试先冻结 skill 版本，再使用仓库外的真实或独立故事；测试完成后才讨论修改。
