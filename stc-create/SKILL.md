# 创作主流程（救猫咪·端到端编排器）

你拿到用户的一个故事方向。你的任务不是一口气写出全稿——LLM 长篇会失焦、人物声音会糊、节拍会变形。你的任务是当**导演**：按救猫咪方法论，分阶段把方向"洗"成完整作品，每个阶段产出可检查的中间物，**用户确认后才进下一步**。

为什么必须分阶段：斯奈德原话——"如果还不能用一两个句子阐明每个节拍，那我还没理清节拍，我只是在猜测，我在踩水即将被淹。"端到端一口气写 = 全程踩水。分阶段 = 每一拍想清楚再下沉。这契合他自己的工作法：案板、索引卡、一拍一拍填，不是一气呵成。

## 流程：8 个阶段，每阶段交付 + 确认

### 阶段 0 · 方向澄清
- 把用户的方向复述成一句话故事线雏形。
- 问清：什么媒介（剧本/小说/短篇/短视频/文章）？大致体量？目标受众？
- 产出：一份"创作简报"。
- → 用户确认后进阶段 1。

### 阶段 1 · 点子验证（调用 stc-idea-check）
- 跑 stc-idea-check 全套：四要素体检 + 十类型识别 + 主干5问 + 原始性初筛 + 改写故事线。
- 产出：验证报告 + 定稿故事线 + 类型 + 主干5问答案。
- 任一关没过 → **不进下一步**，先在 `stc-idea-check` 中改方向；只有创作者本人卡壳、没灵感时才用 `stc-first-aid`。
- → 用户确认故事线立得住后进阶段 2。

### 阶段 2 · 三个世界图景
- 画第一世界 / 第二世界 / 第三世界三个快照（方法见 stc-beatsheet 的"先画三个世界"）。
- 重点检验：第二世界是否和第一世界"相反"？第三世界主角"变成谁"是否清楚？转变幅度够不够？
- 产出：三世界快照表。
- → 用户确认转变想透了后进阶段 3。

### 阶段 3 · 节拍大纲（调用 stc-beatsheet）
- 跑 stc-beatsheet 出 BS2 15 拍大纲，每拍 1-2 句，标 A/B 故事与结构任务。
- 产出：完整节拍表。
- → 用户确认大纲后进阶段 4。

### 阶段 4 · 场景卡（调用 stc-scene-cards）
- 把 15 拍拆成具体场景卡（电影约 40 场；其他媒介按体量换算）。
- 每场卡明确一个主要冲突 `><`、一次情绪/价值转变 `+/-`、可见行动和退出后果。
- 产出：按节拍分组的场景卡。
- → 用户确认分场后进阶段 5。

### 阶段 5 · 分组写作
- **一场一场写，不要一次全写。** 按已确认场景卡写，不在正文阶段偷偷改掉故事主干。
- 每写完一组（如第一幕全部场景），让用户看，确认声音/基调对路再继续。
- 人物台词过"劣质台词检测"（盖住名字能分辨谁说话）。
- 产出：分场剧本/正文。
- → 用户确认后进阶段 6。

### 阶段 6 · 自检回改（调用 stc-diagnose）
- 跑 stc-diagnose：主干5问 + 9条检查 + 绿灯清单逐拍 + 专项检测（示而不讲/坏蛋强度/台词/转折）。
- 产出：弱点清单 + 改写优先级。
- 按优先级回改（致命 → 重要 → 润色），先改致命的。
- → 用户确认改完后进阶段 7。

### 阶段 7 · 对外钩子（可选）
不是每个故事都要对外推介。只有当用户要对外讲/发/卖这个故事时才走：用 `stc-idea-check` 的一句话 logline，加上套件 README“对外推介速查”里的 7 个关键拍产出对外钩子。不对外就跳过。

## 持久化（跨多轮的关键）

长流程会跨多轮对话。**每个阶段产出写到文件**。优先使用用户指定的目录或当前项目结构；用户未指定时，先确认一个可保留的作品目录，不写死某台机器的个人路径。

```
<作品目录>/
├── 01-brief.md          # 阶段0 创作简报
├── 02-idea-check.md     # 阶段1 验证报告
├── 03-three-worlds.md   # 阶段2 三世界快照
├── 04-beatsheet.md      # 阶段3 节拍表
├── 05-scene-cards.md    # 阶段4 场景卡
├── 06-draft/            # 阶段5 正文（每场一文件或分幕）
├── 07-diagnose.md       # 阶段6 诊断+回改记录
└── 08-pitch.md          # 阶段7 推介稿
```

下次继续时，**先读这些文件恢复上下文**，不要让用户重述。问一句"上次到阶段 X，确认进下一步吗"即可。

## 什么时候不用这个 skill

- 用户只想做其中一环（只要大纲 / 只要诊断 / 只要推介）→ 直接用对应分段 skill，别套全流程。
- 方向还很模糊、用户自己也没想清要写什么 → 先用 stc-first-aid 理方向，别硬跑全流程。
- 用户明确"一键出全稿不要我确认" → 说明会采用内部检查点并标记关键假设；尊重用户选择，不用“质量自负”把责任甩回去。

## 注意

- **编排模式：优先使用可用的分段 skill，无法加载时按本文件摘要内联执行。** 不假设任何宿主必然支持 skill 间调用；母 skill 只保留流程与质量闸门，不复制全部框架。
- 互动创作时，每个阶段的确认节点是硬节点。若用户明确要求一次性交付，则在内部保留同样的阶段检查，并把未经用户确认的关键假设标出来。
- 媒介不是电影时，阶段流程不变，把"页码/场景/剧本"换成对应媒介单位。
- 不脑补原书没有的方法。主干5问、三世界、BS2、场景卡和绿灯清单来自书中方法；把它们编排成阶段流程、设置文件名与确认节点，是本套件的组织方式，不是原书固定流程。
