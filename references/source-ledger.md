# 来源账本：救猫咪三部曲划线摘录

这份账本解决两个问题：一是防止整理时悄悄丢掉原始知识，二是防止整理者的推导被误写成作者原话。

## 来源锁

- 来源标识：`救猫咪三部曲.md`
- 来源性质：微信读书导出的 197 条划线、书评与个人想法，不是三本书全文。
- 基线规模：693 行，173,993 bytes。
- SHA-256：`689208a48dcb55309b099165f78f4190debdecfcde7f27005b45a7591b4f9fc7`
- 本轮重构前 Git 基线：`0f287fa2e447c6471e74380280049b97a8b922d7`

原始文件是只读知识源，不复制进公开仓库，也不由本项目修改。每次来源发生真实更新时，应同时更新行数、字节数、哈希和下表；否则视为来源漂移。

## 三类标记

- `[摘录]`：能在上述划线文件的标注行核查。
- `[官方补充]`：划线不足，补自 Save the Cat 官方材料，必须单独写明来源。
- `[整理者延伸]`：为 AI 使用、跨媒介迁移或工作流设计而增加；不能冒充书中固定方法。

个人书评和划线后的个人想法是阅读者理解，不作为“作者原法则”的证据。它们不会被删除，但只能作为灵感或待验证解释。

## 官方补充

“三个世界”的完整定义不在本地划线材料中。当前使用的“第一世界—颠倒的第二世界—综合后的第三世界”来自 Save the Cat 官方第三章材料 `Transformation Machine`；本地摘录 307、512、614 只能支持反主题世界、前后快照和重写时回顾三个世界。该方法在 `stc-beatsheet` 中必须继续标 `[官方补充]`。

## 整理者延伸清单

以下都是为了让 AI 真正能工作而加的，不是书中的固定表格：

- 把完整创作拆成母 skill 与多个单一职责子 skill。
- 每阶段的文件名、确认点、断点续作和路由规则。
- 场景卡中的“时空/视角、即时目标、可见行动、退出后果”。书中直接支持的是索引卡、主要冲突和首尾情绪变化；这些扩展负责把卡片变成可继续写作的交接物。
- 电影方法迁移到小说、短剧和 AI 视频时的体量换算。
- 从场景卡到场景正文，再到未来分镜、Seedance 提示词的生产链；后两者不是《救猫咪》方法。

## 非运行时保留区

这些知识没有被删除，只是不应混进“写一个故事”的 runtime：

- 280–294：作者职业经历、建立关系、经纪人与市场。
- 574–612：原创剧本销售、经纪/经理、市场定位、七点推介。
- 616–618：职业抱怨与经纪关系。
- 629、639–641：搭档准则、换经纪人与职业更新。
- 662–688：创作日记、职业目标、规训/重点/正能量、愿望卡/行动卡。其中能解除当下创作停滞的部分可由 `stc-first-aid` 使用；长期职业规划不进入该 skill。

不进入 runtime 不等于判断它“不重要”。原因只是它们回答的是职业经营问题，而不是当前故事创作问题。未来如确有稳定需求，应基于这些范围另建“编剧职业实践”能力，而不是塞回创作母 skill。

## 已废弃的测试污染

2026-07-30 曾围绕同一个虚构的超级英雄救援题连续修改运行时 skill，并加入特殊能力输入/输出、专业人员与权限、设备承力、多目标期限、秒级倒计时和逐场时间账等规则。该题的故事前提本身没有先通过点子阶段，且每轮测试之间又修改了 skill，因此不能证明这些规则具有通用性。

上述规则已从运行时 skill 删除。原始测试产物保留在 `evaluations/runs/` 作为失败实验档案，不作为《救猫咪》方法、好故事样例或后续创作规范。真实项目若有具体技术、时长或制片约束，应依据该项目单独处理，不能再次写回通用故事法则。

## 防丢失规则

1. 修改方法前先查本表的主责；不得让同一套详细法则在多个 skill 重复。
2. 从 runtime 删除内容时，必须在本表标成“迁移到某 skill”或“非运行时保留”，不能静默消失。
3. 新增规则若找不到摘录证据，必须标 `[官方补充]` 或 `[整理者延伸]`。
4. 诊断可复检生成阶段的指标，但不得复制整套生成流程；只引用产物契约。
5. 原始文件的哈希必须在发布前复核，确保整理工作没有改动知识源。
